# Test and verification plan — 2026-10-17

How each fix is proven and kept from regressing. Priorities match the findings register. New Rust
tests run under `cargo test`; UI checks run in headless Edge against the fake backend (no
hardware). "Live" tests need an agreed test session (hardware writes, under 2 minutes, restore after).

## Principle
Do not turn the suite green by weakening assertions. Each new test must fail against the current
code and pass only after the fix. Security tests assert the **refusal**, not just the happy path.

---

## Must-fix verification

### S5 — toast authorization
- Unit (`remote` or new `actions`): `toast_action("recv:C:\\Windows\\System32\\cmd.exe","open")` with
  no matching toast ⇒ no launch (inject a launcher spy). `toast_action("xfer:1","accept")` with no
  pending transfer ⇒ no accept. An action id not in the toast's declared actions ⇒ ignored.
- Regression: a genuinely queued "File from your phone" toast still opens/reveals (spy sees one call).
- Live/phone (`phone.mjs`): the Open button on a real received-file toast works.

### S3 — env browser flags
- Unit: `browser_args()` with the elevated flag true and `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`
  containing `--remote-debugging-port=9222 --load-extension=x` returns the base flags only; in the
  `test` profile or unelevated it still honours a safe addition.
- Manual: set the variable as the user, start Deck through the logon task, `netstat -ano` shows no
  debug listener; then `elev-install.ps1` with its explicit flag still gives CDP on 9222.

### S2 — DLL search path
- Code review that `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` runs before any load and
  that each vendor load uses `LOAD_LIBRARY_SEARCH_SYSTEM32` or an absolute path.
- Manual (test VM, Process Monitor): no `nvml.dll`/`nvapi64.dll`/`atiadlxx.dll` probe resolves outside
  System32 or the NVSMI folder. Functional: GPU + sensor pages populate on an NVIDIA PC; the sensor
  page still works on a non-NVIDIA PC.

### S1 — install model
- Unit: the task-path guard accepts a Program Files path and rejects a `%LOCALAPPDATA%` path (feed it
  a folder whose ACL is user-writable vs admin-only).
- CI installer smoke test: build the NSIS setup, install silently, assert the exe is under Program
  Files, assert `schtasks /query /tn \Deck\Deck /xml` points there, assert the folder grants write
  only to Administrators/SYSTEM.
- Manual: clean VM, UAC on, release setup, confirm one prompt and correct task paths.

### R1 — settings durability
- Unit (temp dir as the profile): truncated `settings.json` + valid `.bak` ⇒ `.bak` loaded, bad file
  kept as `.corrupt-*`. One field of the wrong type ⇒ other fields preserved (field-merge). Two
  concurrent `save()` calls ⇒ the file always parses afterwards. `save()` leaves a `.bak` equal to
  the previous content.

### R2 — crash guard
- Unit: `hold_back`/`cpu_hold` with an empty file ⇒ hold; with garbage ⇒ hold; with a missing file ⇒
  no hold; atomic write leaves no partial file (write then read-back parses).

### T1 — CI
- New jobs on `windows-latest`: `cargo clippy --all-targets -- -D clippy::correctness`;
  `cargo audit` (or `cargo deny check advisories`); `node regress.mjs && node toast-test.mjs &&
  node a11y.mjs` (fail on any FAIL or script error); `cargo tauri build --bundles nsis` with
  `DECK_REQUIRE_RTSS32=1`. Negative control: a branch without `i686-pc-windows-msvc` must fail the
  build step (proves the rtss32 guard). Upload the setup artifact and its SHA-256.

## High-value verification

- **S6** (peer trust): unit tests on a refactored trust check — a second device with the same pairing
  code but a different device key is **not** auto-trusted and its installer still needs a local prompt;
  the genuine paired device still is. Live: two-PC transfer still works after re-pairing.
- **S9** (phone transport): unit tests for the request-auth helper (valid MAC accepted, replayed/absent
  rejected); `phone.mjs` end-to-end with the token out of the URL; check a strict CSP header is sent.
- **S4**: unit test with the Explorer-automation path stubbed to fail ⇒ `launch_as_user` does **not**
  fall back to an elevated ShellExecute (spy asserts no elevated launch).
- **S7**: temp-folder tests that create a junction between resolve and use ⇒ nothing outside the
  intended root is deleted or written (Clean up, inbox, share zip).
- **S10**: unit test that an incoming Claude Sync settings change adding a `hooks` entry is held, not
  written, until confirmed.
- **S11**: extend the ignored `share::one_time_link` test — two overlapping downloads of a `max=1`
  link ⇒ exactly one completes; a LAN-only link is refused on the Funnel path.
- **R3**: a test that panics while holding an hw lock, then builds the tray menu, must not panic.
- **R4**: live session — set a fixed fan duty, terminate Deck (`taskkill /f`), confirm the watchdog
  releases fans and the GPU fan within a few seconds.
- **R5**: unit test of log rotation; the This PC report contains the log tail.
- **T2**: add unit tests for `clean_rel`/`clean_component`/`resolve_shared` (reject `..`, drive colons,
  ADS, reserved names, out-of-root), the `beam`/`ccsync` handshake (wrong code rejected before any
  frame is parsed, frame-size cap), and `safe_rel`/`classify`.
- **T3**: fix `regress.mjs` check 18 to open the Look tab (expect >10 font options); add Overlay,
  Drives, PC to PC and Claude Code sync to `all.sh` so `a11y.mjs` covers them.
- **U1–U3**: after enlarging the hit areas and labelling the textarea, `a11y.mjs` (with the four pages
  added) reports 0 small targets and 0 unlabelled fields across all pages.

## T4 — ignored tests by risk (2026-10-18)

Run one with `cargo test <name> -- --ignored`. "Safe" means it reads only and changes
nothing the user would notice.

| Risk | Tests | Notes |
|---|---|---|
| **Safe: reads only** | `display` fonts, `gpu::nvml::one_shared_instance_reads_the_card`, `profiles::plans`, `sys` net, `hw::smart`, `mft`, `disk::scan_speed`, `support::live_bits`, `rdesk::status_on_this_pc`, `profiles::cpu` probe, `boost` dry run, `rtss` dumps and `live_ring_stats` | fine during a session; `mft` and `scan_speed` read a whole drive (a few seconds of disk load) |
| **Encoder only, synthetic frames** | `h264` sparse, baseline, backwards, keys, `encoders_live` | uses the GPU encoder; no screen capture |
| **Captures the real screen: never run** | `h264::real_screen_rate`, `screencast::capture_*`, `hw::screen::dxgi_live`, `tiny_picture_sizes` | breaks the "never capture the real screen" rule |
| **Changes visible state** | `rtss_tray_icon`, `time_slot_appears` | touches RivaTuner's tray icon or the overlay; only in an agreed session with no game running |
| **Starts and closes processes** | `boost::close_and_reopen_dummy` | uses a dummy process; harmless but visible |
| **Opens network ports** | `beam` and `ccsync` `two_engines` (bind 0.0.0.0: Windows Firewall prompt), `share::one_time_link` (127.0.0.1 in the test profile, no prompt) | run the two-engine tests only when a firewall prompt is acceptable |

## Regression safety net (run before every release)
1. `cargo test`: expect 205+ passing, 0 failing (update DECK.md when the count changes).
2. `node regress.mjs` and `node toast-test.mjs` — every line PASS.
3. `node a11y.mjs 1260 900` and `node a11y.mjs 900 600` — 0 unnamed, 0 unlabelled, 0 overflow, 0 errors.
4. `cargo clippy --all-targets -- -D warnings`: clean (CI enforces it).
5. `cargo tauri build --bundles nsis` with `DECK_REQUIRE_RTSS32=1` — succeeds and embeds the helper.
6. One live pass on the maintainer's PC (profiles under load, fan release on quit and on kill, phone
   remote, overlay), with everything restored afterward.

## Environmental limits on verification here
- Installers and anything binding 0.0.0.0 were not run (would prompt the firewall or change the
  system). Of the ignored tests, `share::one_time_link` and the NVML test were run and passed.
- Dependency vulnerability scan not run locally; CI runs `cargo audit` (T1).
- P1 was measured on 2026-10-17 (see the migration report). Thread names needed elevation, so the
  threads were recorded by id.
