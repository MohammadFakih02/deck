# Deck UI audit — 2026-10-12

> Screenshots and JSON files mentioned below are kept on the maintainer's machine and are not in the repo.

Scope: the main Deck window (28 pages plus sub-tabs, quick-panel and app-window modes) and the phone remote web app.
Deck is a Windows desktop app (Tauri/WebView2). Its "devices" are window sizes and display scaling, not phones; the phone remote is the one mobile surface.

## How it was tested
- **Fake backend in headless Edge** (`tools/testing/ui-preview`): every page at 1260×900, 900×600 (the window's minimum size), 1280×720 (a 1080p laptop at 150 % scaling), and 1920×1080.
- **Phone remote:** tested at 320×568, 375×812, 430×932, 768×1024 and 1024×768, with touch emulation.
- **Scripted input:** `regress.mjs` sends real mouse and keyboard events over CDP.
- **Live:** the installed build was driven over CDP (every page, script errors, accessible names), and screenshots are in `after/live/`.
- **Browsers:** only Chromium (Edge headless and WebView2). Firefox and Safari are not relevant to the desktop app. The phone remote was not tested on a real phone or in Safari.

## Bugs found and fixed (each confirmed with a failing check first)
1. **Clicks lost on live pages.** Sound, Processes, Network, Disk space, Keep awake, Phone and Home redraw every second. A click whose mouse-down and mouse-up straddled a redraw did nothing, because the button was replaced in between (roughly 1 click in 10). Redraws now wait while a mouse button is held, and the change is drawn on the next free tick (`app.js`, `home.js`).
2. **Keyboard focus thrown away every second** on those same pages. A focused button lost focus to the page body on each redraw. Focus is now put back on the same control (`focusSpot` / `refocus`).
3. **Space typed into the search box.** "Type anywhere to search" also caught Space, so Space on a focused button jumped to the search box instead of pressing the button.
4. **Dialogs.** They had no dialog role, nothing kept Tab inside them, focus didn't come back to the opener, and Escape or a click outside left `confirmBox` / `promptBox` promises hanging forever.
5. **Accessible names.**
   - Switches had no name and no switch role; sliders and drop-downs had no names; the Home media buttons had no names.
   - Fixed with names from the code where the label is known (`settingRow`, `sliderRow`), plus a pass after each redraw (`nameControls`).
   - The current page is now marked with `aria-current`, segmented buttons with `aria-pressed`, and toasts are read out (`aria-live`).
6. **No visible focus on switches**, whose checkbox is hidden with opacity 0. Every control now shows one consistent focus ring when reached by keyboard.
7. **Clipboard detail toolbar.**
   - It clipped the delete button at narrow widths.
   - With "paste on click" off, it showed two identical "Copy" buttons.
8. **Fans page at the default panel size.** The "follows" drop-down was cut off ("Highest of CPU an"). The fan list now gets more of the width.
9. **Very wide windows.** Settings rows stretched to about 1,600 px between label and switch; they're now capped at 1,120 px.
10. **Short windows.** The sidebar was cut off with no sign it scrolls; it now fades at the bottom while there are more pages below.
11. **Tall dialogs** could run off a short window; they now scroll.
12. **Phone remote.**
    - Zoom was blocked (`user-scalable=no`).
    - Ten icon buttons and the sliders had no names.
    - The "All apps" target was too small.
    - The album-art URL wasn't escaped.
    - On a tablet the controls stretched edge to edge; there's now a 640 px column.
13. **Reduced motion.** The system setting is now respected everywhere.

## Checked and left alone
- **Phone taps during the 1.5 s state push:** a tap still lands, because touch clicks go to whatever is under the finger on release. Tested, so no change was made.
- **Network graph empty when the page opens:** it starts recording when you open the page and fills in over a minute. This is working as designed. A backend history would make it start full, but that's a feature, not a bug.
- **Page-switch speed:** already fast, with no measurable bottleneck, so nothing was optimised blindly.

## Not tested / remaining
- No real phone, real screen reader (NVDA/Narrator) or real high-DPI monitor was used; those were emulated or checked by automated rules.
- Destructive actions were not run for real: Clean up, End process, Shut down, uninstalling apps, deleting files. Their confirmation dialogs were checked.
- Hardware-changing controls were not exercised: fans, CPU/GPU profiles and lighting (rule: no hardware changes without the user).
- The in-game overlay was not seen in a game (see `PROJECT_STATE.md`).
- **Mock gaps fixed along the way:** `mock.js` now has real Cooler display data, and `all.sh` now includes the Cooler display page.
